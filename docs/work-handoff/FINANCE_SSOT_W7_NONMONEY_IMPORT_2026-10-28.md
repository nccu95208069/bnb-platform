# W7 OS non-money shadow import contract — 2026-10-28

This disabled candidate adds pre-cutover import routes for historical OS statuses, recurring rules, payout rules, payment accounts and categories. It does not read Redis, run an import, change a finance writer, or establish W7 readiness. Source records still require a separately captured, private, immutable snapshot and per-record review.

## Route and source scope

The existing `finance:import` credential must have origin `finance`, one enabled property-bound connector, and no `cutover_at` for writes. `os_legacy_payment` is the only connector allowed to import `status-commands`; `os_manual` is the only connector allowed to import the other four kinds. Ordinary OS routes keep their existing `finance:status` and `finance:plan` permissions. Imports do not grant either permission to the importer.

`POST /v1/properties/{propertyId}/finance/imports/{status-commands|recurring-rules|payout-rules|accounts|categories}` accepts the corresponding existing command body, a stable `request_key`, required `origin_request_hash` (64 lowercase hexadecimal characters for the exact source record/version snapshot), `source_actor_ref` as `os_actor:` plus 64 lowercase hexadecimal characters from a property-scoped hash of the original actor identifier, and original `source_recorded_at` in UTC ISO format. The original command's field checks and version rules still apply. The source hash, actor, time, normalized input, target reference, property, connector and source version are recorded atomically in private `finance_import_catalog`; the importer credential and import commit time remain separate audit fields. If the original actor or time is unavailable, hold the record for review. Existing `imports/receipts/{requestKey}` is the idempotent receipt readback. A rejected or uncertain source record must stay in `finance_import_issue` or the private review manifest, not be replaced with a guessed value.

`GET /v1/properties/{propertyId}/finance/imports/catalog?limit=50&cursor=...&as_of_change_seq=...` returns only that credential's connector records. Each row contains the original source key/version/hash/actor/time, imported normalized payload, and current normalized target. Pagination is pinned to a property finance change watermark: pass the first page's `as_of_change_seq` on every later page; a changed watermark returns a version conflict and requires a fresh scan. The opaque UUID cursor is ordered for complete traversal, not chronological ordering. A missing target is returned as `target_current: null` and blocks reconciliation. The catalog stays readable after the connector's cutover timestamp so an operator can verify imported history, but new imports are then rejected.

The catalog is private and property scoped under forced RLS. It must not be exported to a public repository: account display names, safe descriptions and source IDs may still be operationally sensitive. The import service never reads the production Redis source directly. The offline transformer must provide deterministic request keys and hashes, retain each source record's evidence privately, compare every source record/version and the final target state, and prove no extra imported rows. `status_only` must have zero cash effect; recurring and payout rules are plans, not payments.

## Remaining gate

No current Redis source snapshot, backup or exact booking alias has been supplied to this candidate. The source-specific OS transformer and a zero-difference run against a real private snapshot are separate W7 deliverables. The synthetic PostgreSQL test proves the route's transaction, authorization, idempotency, non-cash effect, source-scoped readback and cutover fence; it does not prove historical values or production readiness.

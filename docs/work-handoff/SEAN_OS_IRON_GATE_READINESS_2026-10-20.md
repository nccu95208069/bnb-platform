## 已核對的現況

- [遷移計畫](../../iron-gate/SWEETFUN_SHEET_MIGRATION_PLAN_2026-10-20.md)要求先完成備份、全量核對、隔離影子及三入口改接，最後才逐館切換；[執行紀錄](../../iron-gate/SWEETFUN_MIGRATION_EXECUTION_2026-10-20.md)目前仍是唯讀盤點，`canCutover=false`。
- Sean 日曆的 `/api/v1/bookings/calendar` 在正式 Sheet 模式透過 `readCalendarSources` 讀主表快照，再讀即時表格補旅客資料並疊加 OS 收款；沒有水芳 Iron Gate 來源選擇或新舊權威切換。日曆型別是一筆實體房間的住宿片段，使用 `property_id="sweetfun"`、`room_id="sweetfun-101"` 等舊識別。
- Sean 的 `/api/v1/order-payments` 以 `SF-...` 來源訂單 ID 查帳，寫入私有收款帳本，並可能回寫主表 H 欄／註記。`finance-summary` 也直接重新讀主表。只把日曆改讀 Iron Gate 會讓畫面、收款和財務查詢分屬不同正本。
- Iron Gate 已有 `GET /v1/properties/{propertyId}/bookings`，以 UUID 館別及分頁查詢，訂單有多段 `stays[]`、實體房 UUID、狀態與版本；目前的授權讀取投影只有可選的訂單總額和收款總計，沒有 `bookedAt`、通路／來源別名、逐房晚金額、逐筆收退款與舊來源 J/L/N 對照。現有 OS 只讀影子橋接面向 BnB SaaS 客戶工作區的單筆 UUID 查詢，不是 Sean 日曆的資料來源。

## Sean OS 端工作與切換門檻

1. **先定讀取契約。** Iron Gate 補齊上表中目前缺少的來源、房晚價格、付款及占房／待核投影；確認 Sean 專用授權與 UUID 對照。OS 增加一個伺服器端受權讀取適配器，輸出現有日曆、訂單查詢與財務畫面可理解的資料；不得把機器憑證送到瀏覽器。
2. **用影子讀取驗畫面。** 在舊 Sheet 仍為正本時，對同一來源版本逐房晚、逐父單、逐筆收退款比較 Sheet／OS 與 Iron Gate。合成測試至少涵蓋多房連住、中間空檔、改房、取消、保留、付款／退款、未知價格、重複來源事件和讀取失敗。實際來源的每一列及財務事件仍須由工程端全量核對。
3. **把寫入端一併改接。** Sean OS 收款及 H 回寫、原生訂單／封房、Gmail check order、LINE 指令與 OwlNest 操作都要逐一證明只寫當前權威；不能只換日曆 API。停窗排空、最終差額匯入、讀回、備份還原與回退演練完成後，才可對水芳切換。
4. **切換後驗收。** 用受權帳號在 Sean 版實際查一筆既有訂單、新單、改單、取消及收退款；對照來源 ID、房間／日期、狀態、金額、付款、來源時間與 Iron Gate 回讀。任何未解釋差異都維持舊權威及 `canCutover=false`。

截至本次檢查，以上第 1–4 項尚未完成，不能保證 Sean 版在遷移後無縫使用。此判斷以目前程式與文件為準；Iron Gate 欄位契約或遷移實況更新後必須重驗。

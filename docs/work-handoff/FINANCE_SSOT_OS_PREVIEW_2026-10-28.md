# Sweetfun OS finance SSOT: preview before confirmation

The SSOT-enabled Sweetfun finance form now asks the operator to review a server-generated summary before it sends a write. Booking-linked receipts and voids call Iron Gate's read-only `commands/preview` endpoint. Account, recurring, payout, and unlinked money actions use the same OS validation rules to prepare a local summary. Cancelling the dialog sends no finance command and creates no pending request.

The preview response carries a ten-minute OS-signed proof bound to the actor, property, request ID, intent hash, projection version, and exact prepared command. For booking-linked money, it also contains the resolved Iron Gate command and its booking snapshot token. The confirmation submits that original command and request key. The OS checks the original receipt on uncertain outcomes and on retry; it does not silently obtain a new preview after a version conflict. The pending record begins only after a valid proof reaches the write endpoint. Once a pending request exists, a missing receipt keeps that request blocked for review, even after preview expiry or a later projection change. A retry only looks up the original receipt; it never sends another command automatically.

Iron Gate has no read-only preview endpoint for account, category, recurring, or payout plans. Their OS preview is a validated local summary, and a custom category may still be created after confirmation before the associated finance command. If the second command fails, that category can remain; the original request remains available for receipt lookup and manual reconciliation.

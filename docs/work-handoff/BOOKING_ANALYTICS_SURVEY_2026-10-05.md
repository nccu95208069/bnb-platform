## 2. 共同架構：本產品的設計推導

以下是依上述功能整理出的產品設計，不是宣稱我們擁有競品的資料供應或預測能力。

1. **先定範圍**：期間、旅宿、通路、房型與資料快照時間。
2. **先講結論**：這段時間有什麼變化、主要來源在哪裡、應先注意什麼。
3. **再看數字**：房晚、房費、平均房價、資料覆蓋；各指標口徑一致。
4. **拆出原因線索**：日期趨勢、通路／房型組成、星期、住宿長度、提前預訂。
5. **分開過去與未來**：已發生的住宿紀錄、未來目前已訂、期間新增接單是不同問題。
6. **給下一步**：每個建議帶一個可核對的依據，而非對任何資料都顯示同一句話。
7. **補足資料才升級結論**：庫存、成本、取消／改期歷史、同時點快照、競品市場基準各有用途。

## 3. 舊版主要問題

- 問答只讓 Gemini 選最多五個 fact IDs；普通的「最近訂房表現如何」沒有專用工具，容易回傳空答案。fallback 甚至明確拒絕「這個月」「建議」等常見問法。
- 報告只有整份資料的總數和月度／通路圖，沒有統一的日期、通路及房型篩選。
- 「有效明細已整理」是處理狀態，不是經營洞察。
- 每個星期的總房晚沒有除以期間內該星期的出現次數，無法公平比較星期分布。
- 資料不足時只留下空指標，沒有解釋能先做什麼及要補哪種資料。

排查證據：正式站 01:19:43 的問答 POST /api/order-health 回應 200；近期請求亦為 200。這是回答能力與分析設計問題，沒有觀察到 HTTP 故障。

## 4. 本次實作

| 模組 | 這次更新 | 解讀界線 |
| --- | --- | --- |
| 分析範圍 | 近 7／30 天、本月至今、上個月、未來 30 天、全部、自訂日期、通路及房間篩選 | 「最近」按台灣日期，近 30 天不含今日；資料快照時間獨立顯示 |
| 經營快報 | 期間房晚、已知房費、前期紀錄差異、主要通路及建議 | 前期只是同份來源中的紀錄差異，沒有宣稱已核實的全店成長率 |
| 趨勢 | 日／月圖，可切房晚、房費和平均房晚價格；數據表與 CSV | 未知金額保留空值，不畫成房價零；跨晚總價平均分攤 |
| 通路／房型 | 期間房晚、占比、房費、均價，可點名稱進一步篩選 | 房型數不同不能直接以總房晚比較住房率；通路房費不是淨收益 |
| 星期 | 各星期的平均可見房晚，除以該星期出現次數 | 不假設這是住房率；週末定義五、六，國定假日未另分類 |
| 客人習慣 | 平均住宿長度與分布、平均提前天數與分布 | 以入住房次加權；每晚拆列時，無法還原整次住宿便不推算 |
| 未來已訂 | 未來 30 天目前已訂房晚與已知房費 | 是快照內既有訂房，不是需求預測 |
| 下訂日 | 近期建立、目前仍有效的房晚 | 不叫淨 Pickup；取消與改期歷史不完整 |
| 小芳 | 辨識問題→選分析主題／期間／維度→工具計算→回答結論、依據與下一步 | 模型不自行算數、不更改來源、不生成無來源的市場／成本數字 |
| 可信度 | 金額覆蓋、納入／排除原因、指標來源、待補資料 | 取消資料列數不包裝成訂單取消率 |

平均房晚價格沿用既有「正金額房費／正金額房晚」口徑，不把未知或零元算入價格分母。它不是已核對稅費的標準稅前 ADR，不能直接與外部市場 ADR 比較。[Cloudbeds 標準指標定義](https://myfrontdesk.cloudbeds.com/hc/en-us/articles/36232286180763-Occupancy-and-Financial-Reporting-Calculations-in-Cloudbeds)可作未來建立統一財務口徑的參考。

## 5. 資料和程式架構

`唯讀來源 → 明細驗證與隔離 → 住宿房晚 → 日期×通路×房間彙總 → 期間／前期 → 指標與洞察 → 小芳`

- 既有租戶、旅宿、角色、同源與速率限制保留。
- 新報告保存去除住客欄位後的分析彙總與來源列號，仍加密保存 30 天；原解析明細仍 24 小時。
- 分析彙總超過 25,000 個日期／通路／房間組合時，保留日期總覽，不聲稱可使用細分維度。
- 在原始明細仍有效時，既有已完成報告可自動建立 v2 報告，先核對房晚、房費、均價與旧報告一致，再以 CAS 原子更新目前報告；原報告 key 保留。
- 原明細已到期時，舊彙總仍可查看及問答，精確日期篩選需要重新匯入。
- 小芳的模型只規劃工具參數；算術與回答的數字由程式產生。可接續對话中的期間／主題，AI 無法使用時以同一分析工具回覆。

## 7. 檢查紀錄與限制

- TypeScript 與本次變更檔案 ESLint 通過，未新增或執行測試。
- 原報告的核心房晚、房費和均價不改口徑；自動升級時再次比較這三個值，不一致就保留原報告。
- 瀏覽器工具仍因無法驗證管理員安全政策而拒絕存取，未繞過限制。因此目前未完成正式站視覺、使用者真實報告升級及實際 Gemini 問答驗收。

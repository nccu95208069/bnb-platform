# Account interface languages — 2026-09-08

Four supported locales: Traditional Chinese (`zh-TW`, default), English (`en`), Thai (`th`), Vietnamese (`vi`). Settings → interface language saves immediately for the authenticated account. Login also exposes a device preference for the unauthenticated screen.

`GET/PUT /api/account-language` reads/writes only the session principal's preference. PUT requires same-origin authenticated access, accepts only a supported `locale`, and verifies authoritative readback. Redis key `sweetfun-os:language:v1:<encoded principal id>` has no expiry. No account id can be supplied by the caller. Failures are visible and do not claim a successful save. Cookie rendering avoids an initial Chinese flash; the stored account preference remains authoritative across devices. Language selection does not change roles or property scope.

Authored UI copy is translated explicitly through the typed language context and source-key catalog, including navigation, calendar, payment forms, finance, settings, and account screens. Guest and account names, property names, original notes, user descriptions, room ids and platform identifiers remain original. There is no DOM-wide translation or external translation service. Unknown strings retain their source text. New interface strings must be added to all three translations.

Formatting uses each locale while retaining Gregorian dates (including Thai), existing business time zones and TWD amounts. API enums, calculations, stored source data and Agent contracts are language independent. Locale selection only affects presentation.

Validation: catalog completeness and placeholder parity; supported locales and Gregorian Thai formatting; name preservation; account isolation, verified persistence and invalid-locale rejection; anonymous/cross-origin endpoint denial. Existing finance/payment regression suites cover unchanged financial behavior.

Follow-up: generated source detail values (linkage explanations, payment labels, missing-data notices, guest counts/night counts) are translated at their typed display sites. Recognized guest requirement tags translate while raw names/notes remain unchanged. Identifiers are never sent through translation. Travel-card and travel-subsidy tags remain distinct. Added regression coverage for screenshot-reported field values in all three non-Chinese locales.

# Sweetfun Iron Gate calendar load incident — 2026-10-22

The owner reported that the production month calendar and property selector remained in their loading states after the Sweetfun Iron Gate read cutover. The authenticated production API returned Iron Gate inventory version 17 and both properties for a one-month request. The same account's week view rendered bookings. The actual month-view request covered `2025-01-01` through `2028-01-01`; that request returned HTTP 503 with a private, no-store error response. The UI had previously been accepted with a one-month API probe, which did not exercise the browser's initial request.

The month-view client now requests only the dates shown in the selected month's calendar grid. A user swipe or month navigation advances the anchor and requests that new grid. The scroll target is updated before the scroller remounts after an uncovered read. Search results are explicitly labeled as limited to the displayed dates; cross-year search needs a separate bounded search design before it can be restored. This avoids falsely presenting an incomplete result as a full-history search.

The production sidebar uses a public, non-secret `NEXT_PUBLIC_IRON_GATE_SWEETFUN_CALENDAR_ENABLED` flag to describe Sweetfun's Iron Gate read path and Offland's continuing Sheet source. The server's private source switch remains the authority. Server errors retain a safe Iron Gate diagnostic code in logs and show a source-neutral calendar error to users. No booking writer, credential, authority epoch, or source data is changed by this patch.

Verification: focused request-window and Iron Gate reader/route tests passed (10 tests), frontend TypeScript and targeted ESLint passed, a production webpack build passed with the public UI flag enabled, and all three PR #61 CI jobs passed for code commit `407f3df`.

Production release: Vercel deployment `dpl_DQyfX2SnW1gGKeBuDoDDEEK3zhGn` reached READY and was aliased to `https://sweetfun-os.vercel.app`. The non-secret public UI flag is scoped to Production. In an authenticated owner browser, the October month view finished loading, showed both property selectors, the corrected source banner, and 149 Sweetfun room nights. Navigating to November and then scrolling to December produced visible booking cards in both months without an error. The new deployment's runtime error and warning scan was empty at the acceptance checkpoint. The Gmail writer and Iron Gate authority were unchanged by this release.

Remaining product work: cross-year booking search is now explicitly limited to the currently displayed date range; implement bounded historical search without treating an incomplete result as a full-history search. The calendar is still a read-only booking projection and does not claim OwlNest channel stock or finance authority.

## Follow-up: channel colors and mobile loading

The owner then reported that all Sweetfun cards had the same cream color and the month view still felt slow on a phone. The Iron Gate projection had hard-coded every imported booking's platform to `other`, although its authenticated booking read included the original Sheet platform in `sourceCalendar`. The OS now applies the same exact Sweetfun channel mapping as the former Sheet calendar; unknown source labels remain `other`. Booking and availability reads begin concurrently and still require matching inventory versions plus a final readback. The month scroller mounts at most five nearby months instead of all 36. When one property is selected, the API reads only that property's source, while returning the authorized property list for the selector; it also reuses the authorization result within the request.

The focused calendar tests, TypeScript, ESLint, local production build, and all three PR #61 CI jobs passed for the follow-up code. Production release `sweetfun-mi2vz7c3e-sweetfuns-projects.vercel.app` is aliased to `https://sweetfun-os.vercel.app`. Authenticated browser verification showed October's 149 Sweetfun room nights, Booking/Agoda/direct channel labels, five mounted months, no load error, and successful switching to Offland and back. These checks confirm behavior, not a specific phone latency; network and device timing can still vary.

## Follow-up: uninterrupted month navigation

Month navigation still caused a full-screen loading state because every newly visible month changed the request window. An initial attempt to read five months in one background request caused an Iron Gate calendar 503; that deployment was immediately replaced with the previous accepted version. The final repair keeps each server read limited to one calendar grid, requests adjacent months separately after the current month appears, and retains a bounded in-memory cache for the mounted owner view. Cached windows are combined only when their date ranges overlap and their inventory versions match. An unloaded neighboring panel is labeled as unloaded instead of showing zero bookings. Access loss clears the cache.

Production deployment `dpl_54hLPsCezanKnXr4hn1y6bZ3bDAv` is READY and aliased to `https://sweetfun-os.vercel.app`. In the authenticated owner browser, October showed 149 room nights; background reads filled September (143) and November (95), then December (80) after navigation. Moving October → November → December → October did not show the full-screen loading state or a stale-data warning. No calendar API 5xx appeared in the deployment's post-release log scan. Focused tests (8), TypeScript, targeted ESLint, and the Vercel cloud build passed. Physical 5G device timing was not measured. This change did not alter the booking writer or Iron Gate authority.

# 水芳訂單／房況最短遷移路徑

決策日：2026-10-21（Asia/Taipei）。業主決定本輪**不搬財務**，並允許切換初期暫停水芳 LINE 新增／修改／取消訂單。此文件縮小[原完整計畫](SWEETFUN_SHEET_MIGRATION_PLAN_2026-10-20.md)的首批切換範圍；舊資料與備份仍保留。

## 這輪完成的定義

1. Iron Gate 保存水芳每張有效訂單及每個房晚，保留原 Sheet J／L 身分和私人原列證據；歷史衝突維持隔離，不開放錯誤的可售房晚。新增、改單、取消的唯一正式訂單落點改為 Iron Gate，來源處理結果有可重試的回執。
2. 原 Sheet 保留為可回查的歷史紀錄，不被遷移工具改寫。既有財務帳本、Sheet H 與財務分頁維持原系統，不被解讀成 Iron Gate 付款事件；新訂單若尚無可用的舊財務流程，介面須明示該限制，不能顯示虛假的已收款。
3. Gmail 的新單／改單／取消能在 Iron Gate 讀回後才完成郵件；水芳 LINE 訂單寫入在首批切換時封住，OFFLAND 不受影響。OS 人工訂單入口及訂單／房況讀取、通路房量如何更新，均須以真實端到端測試證明，不能只依一份設計文件宣稱可用。

## 為了加快而刪去的工作

- 不等財務來源全量對帳、銀行／刷卡憑據、付款事件轉換或財務報表改接。本輪既有四類財務來源只作受限保存，不參與上線判定。
- 不要求長期 Gmail／LINE／OS 同時寫入兩個正式帳本，也不把影子事件長期觀察作為前提。改用**有停寫窗口的最後快照**：先演練，停舊 writer，排空在途工作，取最後來源版本，單次匯入差額並逐筆讀回，再切唯一權威。
- LINE 訂單指令暫時停寫，不在首批切換中實作 LINE→Iron Gate 訂單編輯器。LINE 查詢／開關房與 OFFLAND 分別檢查；任何仍依賴舊 Sheet 房晚的操作，在資料源改接前也須停用。

## 最短執行順序與不可省的閘門

| 順序 | 工作 | 可驗收結果 |
| --- | --- | --- |
| A | 修妥私有 Gmail／LINE 候選測試；在零流量候選上驗證設定與停寫開關。 | CI 綠燈，正式舊 revision 與流量未變。 |
| B | 對照實際 writer：Gmail 即時與補收、LINE 所有訂單路徑、人工 Sheet／Apps Script、OS 訂單入口及通路房況。 | 每條舊寫入都有停寫／排空／回復方式；未知 writer 阻擋切換。 |
| C | 實作 Gmail→Iron Gate 的訂單事件與來源身分接線，以及 OS 人工訂單與讀取路徑；用合成訂單完成新增、修改、取消、重試、衝突、斷線讀回。 | 每一成功回應可用同一事件鍵讀回；不確定結果不重送成第二張單。 |

目前 A 的私有候選分支已具備水芳 LINE 停寫旗標，Gmail 來源寫入轉接器已送到私有草稿 PR，尚未部署。C 的 Iron Gate 來源訂單唯讀查詢與歷史 J／L 連結規劃已通過合成測試；來源連結尚未套用到正式影子，正式來源憑證也未發放。Gmail 轉接器在回執與來源查詢都吻合後才將新單／改單／取消視為成功；換卡通知先核對原訂單，來源改單不沿用可能過時的匯入金額。B、D 最後版本與 E 未通過。專用 Supabase 仍是唯讀影子版本 4（1,607 張訂單、1,759 房晚）；正式 Iron Gate Production 仍回 503，Gmail／LINE 正式舊 revision 仍承接 100% 流量。**目前不能切換。**

入口盤點的新發現：現有 Sean OS `/calendar` 的改期／取消是瀏覽器本機示範狀態，畫面也標明「變更只保存在這台裝置」；正式 `/api/v1/bookings/calendar` 只有讀取。因此目前沒有可沿用的水芳 OS 正式人工新增／修改／取消入口。若首批切換也能暫停人工直接訂單，可把這個入口移到後續批次；若不能暫停，必須先完成有館別授權、同鍵回執和通路房量核對的正式人工入口，不能把示範操作當成已接線。

最新來源水位：原主表修改時間 2026-10-21 07:40:38 UTC。相對 03:41 UTC 的私人版本 4 副本，逐 J 對照有 1 筆消失、無新增、214 列移動；其餘 1,762 筆 A:S 值完全相同。消失的是 101 房 2026-10-25 的單晚 Agoda 訂單，且仍占用版本 4 影子的一個房晚；同秒的 Gmail 成功通知稱該訂單刪除 1 筆。通知與來源差額是調查線索，不能代替業主確認或有來源鍵的持久寫入回執。未確認前影子維持原占房，不將該晚放出。

最後快照版本確定後，`scripts/stage-sweetfun-source-links.mjs` 可用受限資料庫角色把既有 J／L 對應的來源連結一次寫入唯讀影子，並在同交易回讀；重跑須得到相同連結，不增減房晚、付款、權威代次或來源憑證。來源鍵改成 JSON 陣列文字，避免 PostgreSQL JSONB 不接受的 NUL 字元。合成 PostgreSQL 15／RLS 實測：首次寫入、同版重跑、錯版本拒絕、管理角色拒絕皆通過。正式影子尚未套用，必須先處理上述消失的房晚並固定最終副本。

若 C 的人工入口或 E 的通路房量無法證明，應只交付已核對的唯讀資料搬遷，不把它稱為正式營運切換。兩個隔離還原資源按業主先前指示保留。

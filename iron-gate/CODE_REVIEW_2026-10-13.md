# Iron Gate 程式碼審查紀錄

日期：2026-10-13（Asia/Taipei）
範圍：目前的合成 API 核心、HTTP 邊界、憑證、SQLite／PostgreSQL 儲存、OpenAPI，以及唯讀 OS 候選轉換。未審真實 OS／OwlNest 連線或舊館遷移，因為尚未接入。

## 已修正的高優先級問題

| 嚴重度 | 發現與可能後果 | 修正 |
| --- | --- | --- |
| P1 | 同一來源連續衝突時，新 fence 會覆蓋舊 fence，舊房晚可能恢復接單。 | 合併所有受影響房晚；測試重複衝突及後續撞房。 |
| P1 | 已存在的外部訂單取消後沒有 tombstone，後到 upsert 可自動復活訂單。 | 取消連結訂單也記 tombstone，復活進人工核對。 |
| P1 | OwlNest 館的外部取消可立即釋出本地占房，沒有逐晚通路證據。 | 取消進待核對並保留房晚保護；真實 provider 讀回前不釋出。 |
| P1 | 通路操作可用操作建立前的讀回標成已完成。 | 要求觀測時間晚於操作建立時間；不合格讀回拒絕。 |
| P1 | 已取消／撤銷的來源或錯誤通路 grant 有機會讀舊結果或操作細節。 | 每次授權重新核對 active 來源 grant、通路 grant 與網站 binding；通路操作也限定當前 connector。 |
| P1 | 保留可走一般取消留下矛盾狀態；保留到期後同鍵重試反而失敗。 | 保留只能走 release；同鍵收據在新的到期檢查前回傳。 |
| P1 | 財務服務沒有受限寫入身分。 | 新增 finance 身分，只能讀指定欄位／事件並追加收退款；拒絕改房與取消。 |
| P1 | 來源複合鍵以分隔字元組成，若外部 ID 含控制字元可造成不同來源身分碰撞。 | 來源識別與版本等必要字串拒絕控制字元。 |
| P1 | 原本只有去個資事件，缺少操作者與請求鍵，無法完整追查取消或改單。 | 每次接受的寫入同交易追加稽核紀錄；PostgreSQL 執行角色不能讀取、更新或刪除稽核表。 |
| P1 | 既有 OS 快照若含新欄位或跨館孤兒訂單，簡化轉換可能遺漏資料並誤報可遷移。 | 唯讀盤點拒絕未知訂單欄位、重複 ID、孤兒訂單；候選只接受已映射的原生子集，預設唯讀且沒有啟用流程，原始訂單完整留存於私密快照。 |
| P1 | OS 簽發會員證明時若把未知角色、非布林全館授權或重複會員當正常資料，可能擴大個資或館別權限。 | [只讀證明元件](../docs/work-handoff/IRON_GATE_OS_PROOF_2026-10-13.md)逐項拒絕這些狀態；簽章只含讀取動作。 |
| P1 | 新增影子路由若只靠機器憑證設定便意外開啟，可能把尚未核對的影子訂單顯示給會員。 | 加上獨立 `IRON_GATE_SHADOW_ENABLED=true` 開關，預設 503；正式啟用仍須逐館核對。 |
| P1 | OS 影子路由若無限制地讀取 Iron Gate 回覆，錯誤上游可耗盡記憶體或回傳超出會員欄位權限的資料。 | 逐串流限制 64 KiB，驗證館別／訂單／工作區、欄位白名單與會員授權；錯誤僅回固定代碼。 |
| P1 | 服務若用高權限資料庫帳號，或遠端 PostgreSQL 連線未驗主機憑證，可能旁路資料隔離或外洩訂單。 | 啟動時拒絕管理、可更改憑證／稽核／事件的角色；遠端連線只接受 `sslmode=verify-full`，禁止連線字串覆蓋 host 或 SSL。隔離資料庫實測受限角色可啟動、管理角色拒絕。 |
| P1 | 既有憑證列、OS 會員驗證結果或未來的新驗證 adapter 若格式異常，字串的 `includes` 可能被誤用為館別／動作比對。 | 每次驗證重查憑證形狀與來源專用範圍；領域層也要求館別、動作、欄位為陣列，異常直接拒絕。 |
| P1 | 影子盤點若直接輸出未知 JSON 欄位名稱，私密來源可在欄位名稱中攜帶客資。 | 未知欄位只輸出固定 `unknown_field`；CLI 的解析／驗證錯誤也只輸出固定代碼。 |
| P1 | 保留單釋出後的晚到款項若只記一般付款事件，業主待辦會漏掉退款處理；若重新占房則可能撞房。 | 保留原收款事件，設定 `latePaymentReview`；退款後淨收為零才清除標記，房晚維持釋出。 |
| P1 | 無金額權限的 OS 會員可能從保留物件看到晚到款項標記；影子路由若只檢查頂層欄位，巢狀住宿或付款物件可能帶入未授權資料。 | Iron Gate 依欄位權限遮蔽保留的款項標記；OS 影子回覆另檢查住宿、保留及付款摘要的巢狀白名單並拒絕異常回覆。 |
| P2 | OwlNest 關房仍待讀回時若先記了一筆付款，訂單版本變動會把正確房晚讀回誤判為分歧。 | 以同一操作鍵及訂單狀態／房晚核對，不讓非房晚欄位版本變動造成假警報；取消或改變操作鍵仍拒絕舊讀回。 |
| P2 | 房況查詢逐格重新展開全部訂單房晚，館別與日期較大時會耗費大量時間與記憶體。 | 每次查詢先建立占房／封房索引，且將回覆限制在 4,096 房晚。 |
| P1 | 通路讀回若只回送期望的 `open/closed`，可把尚未真正關房的庫存標為已驗證。 | 改為要求每個房晚的實際 `count` 與 `isLock`；完整但仍可售的讀回維持 `review_required` 和 fence。真實 connector 仍需驗證證據來源。 |
| P1 | 共用 PostgreSQL handler 若被另一種部署方式直接引用，可能略過私有入口的 TLS 與資料庫執行角色檢查。 | 建立 handler 時必須提供與連線池相同的安全 URL，拒絕額外主機／SSL 覆蓋；首個請求前核對受限角色、RLS 與 schema，失敗只回固定 503，且不查憑證。 |
| P1 | 共用 OS 機器憑證下，不同成員若取得同一請求鍵，可讀回或重播別人的寫入收據；金額權限撤銷後付款收據仍可能顯示淨收。 | 收據與防重判斷加入經驗證的 `subjectId`，讀回付款結果重新檢查 `money` 權限；付款寫入本身也要求該權限。 |
| P1 | Vercel 的命名萬用路由在建置後自動把擷取路徑加成 `?path=...`，使 OS 對原始 path/query 的短效簽章失效。 | 改用無命名擷取的 `/v1/(.*)` 規則；檢查實際 `.vercel/output/config.json` 的目的地不再帶額外 query。正式預覽仍須做 OS 端到端驗證。 |
| P2 | 共用 PostgreSQL handler 首次遇到暫時性資料庫斷線後，會把失敗的安全檢查永久快取到同一個暖實例，資料庫恢復仍持續回 503。 | 暫時性查詢失敗時清除快取，下一個請求重新檢查；不安全角色或 schema 仍維持關閉。測試斷線後恢復。 |

PostgreSQL 執行角色只能透過高熵 token 摘要查單筆憑證，不能列舉憑證表；發證與撤銷須另用管理連線。權威資料、占房唯一鍵、fence、收據與 outbox 在同一館別交易提交。

## 尚未達到的上線門檻

- **OS 影子路由尚未正式配置與舊 writer 封寫**。只讀路由已在獨立分支實作逐請求 OS 會員重讀及短效證明，預設關閉、未部署、沒有真實機器憑證。未注入 verifier 時 Iron Gate 拒絕 OS 憑證。不能將影子路由視為新訂房正本。
- **現有 OS 欄位和保留／付款語意尚未無損對齊**。逐項差異與封寫範圍見 [OS 接線差異](OS_INTEGRATION_MATRIX.md)；不能直接把舊訂單重建成簡化的 Iron Gate 訂單。
- **沒有真實 OwlNest connector、網站一次性報價、LINE 預覽確認、財務憑據核實與人工解鎖流程**。通路執行器只有注入式模擬測試，正式 OwlNest 寫入 API 規格、逐館 lease 和測試授權仍未取得；相應危險路徑保持拒絕或停售。
- **沒有正式環境的私有部署、TLS、備份還原、監控、outbox 消費者與逐館遷移演練**。SQLite 僅供單機驗證；PostgreSQL 測試與一次性資料庫備份還原只在隔離的 localhost 完成。

這些是上線阻擋項，尚無真實接線程式可完成整合審查；不能解讀為整個產品已通過 P1 審查。

## 驗證

- `npm test`：54 個合成測試通過；3 個 PostgreSQL 測試在預設執行時跳過。
- `npm run check`：TypeScript 嚴格型別檢查通過。
- `npm run build`：編出可直接載入的 JavaScript，產物中不含 `.ts` 匯入；缺少設定的正式入口拒絕啟動。
- `npm run test:pg`：隔離 localhost `iron_gate_test` 的 3 個交易／RLS／憑證與共用 handler 測試通過。
- `npm run test:restore`：在同一隔離 PostgreSQL 實例建立並清除兩個一次性資料庫；5 張資料表、outbox 序列與受限執行角色在備份／還原前後核對通過。這不是正式館別的還原驗收。
- `npm run test:server`：127.0.0.1 上的 1 個實際 HTTP 請求流程通過。
- `npm run start:private`：缺少資料庫設定時會拒絕啟動；隔離 localhost PostgreSQL 實測受限角色可啟動後立即關閉，管理角色被拒絕；尚未在正式環境啟動。
- Vercel：新 `sweetfuns-projects/iron-gate` 空專案已建立，本機 `vercel build` 通過並包含 Node.js 22 函式、`dist` 與 PostgreSQL 驅動；入口缺少私密設定或遇到不安全連線只回 503。尚未部署或接上 Supabase。
- `openapi.yaml`：17 個路徑；讀回 schema 使用觀測庫存與鎖房資料，YAML 與 91 個本地 `$ref` 均解析通過。
- OS 分支：會員證明及只讀轉發 4 個合成測試、TypeScript、lint（零錯誤）及 Webpack 正式建置通過；另以合成請求驗證 OS 簽發與 Iron Gate 驗證器互通。路由預設關閉，尚無正式憑證或真實會員請求。
